# Plus4 Grease source review

Reviewed 2026-11-23 for possible adoption through the Plus4 configuration repository and hlab. This is a source review, not a deployment or a printer validation. Only local synthetic diagnostic fixtures were exercised; no operational Grease command was run and no printer was contacted.

Source snapshot: [JarvisAKF/Plus4-Grease, commit abc21a33b73758d34573d5f80de6b436d3241564](https://github.com/JarvisAKF/Plus4-Grease/tree/abc21a33b73758d34573d5f80de6b436d3241564), version 0.12.0. Recommendations below concern upstream behavior; local comparison with our active profiles and hlab follows.

The owner subsequently authorized 300 mm/s tilt/mesh speeds and an independently
implemented Box drying controller with the timer and live-limit fixes described
below. Current usage is in the [Box profile instructions](../printers/qidi-firmware-1.8.2-beacon-box/README.md).
The comparisons below retain the reviewed source/configuration baseline.

## Decision for our stack

Adopt the Box runout-delay removal, then add persistent USB-event evidence to the existing hlab/Klippee diagnostics path. Keep probing-speed changes optional pending measurement. Do not adopt the chamber policy, replace our fan policy, or bundle a second Fluidd or dryer controller into routine fixes.

| Grease feature | Our repository state | Decision |
|---|---|---|
| Runout-flag delays | The active QIDI/Beacon/Box profile still has `G4 P100` inside the sixteen-iteration loop. | Worth implementing in that profile and as a narrowly matched hlab option. Removes 1.6 seconds of explicit dwell; retains all sixteen saves and Box initialization. |
| Shorter stock G29 save delay | Our Beacon G29 calls `_FIND_Z_EQUALS_ZERO` and `BED_MESH_CALIBRATE RUNS=2`; it has no stock `SAVE_CONFIG_QD` block. | No change to either current profile. A future stock-probe-only option needs separate validation. |
| 300 mm/s tilt and mesh | Both active profiles use 200 mm/s tilt and 150 mm/s mesh. The QIDI G29 also caps mesh acceleration at 1000 mm/s². | Optional tuning experiment, not a default defect fix. Validate each printer's reachable area, repeatability and mesh quality first. Grease's stock-grid timing gains do not establish our Beacon gains. |
| Persistent USB log | Klippee already collects kernel/service journals and USB topology; hlab exposes diagnostic upload. The reviewed collector has no Grease-style persistent USB-event source. | Worth adding to hlab's host-maintenance path, with collection and parsing support in Klippee. This preserves evidence that a power cut can otherwise lose. |
| Temperature-driven board fan | Both profiles already use PC4 for a host-temperature-controlled, upgraded 80 mm fan. Mainline also has a separate PB2 controller fan. | Do not transplant stock PC4 fan settings. Driver-temperature input could be evaluated later if measured temperatures or noise justify it. |
| Balanced chamber | QIDI example uses its physical thermistor with its own 0.6 duty/85 C limit and PID; mainline uses the thermistor with a 0.4 duty/70 C limit and separate chamber guard. | Do not normalize either profile to Grease's weighted sensor or thermal limits. These are different thermal policies, not interchangeable fixes. |
| Box drying and extra Fluidd | Mainline already has its own chamber-drying utility, which is distinct from Box drying. Grease adds another Box/UI control path. | Defer to an explicit feature request; fix the dryer concerns below before any reuse. |

Profile evidence: [QIDI print start and G29](../printers/qidi-firmware-1.8.2-beacon-box/gcode_macro.cfg), [QIDI hardware and probing settings](../printers/qidi-firmware-1.8.2-beacon-box/printer.cfg), [mainline hardware and probing settings](../printers/mainline-klipper-beacon/hardware.cfg), [mainline drying utility](../printers/mainline-klipper-beacon/utility.cfg). ### Implement through our existing boundaries

The runout change belongs in the reusable QIDI profile and in hlab's existing `printer firmware fixes` transaction, with an explicit performance option rather than silently expanding its safety-fix defaults. Match only the intended `PRINT_START` runout loop in the resolved include graph. Treat the already-trimmed form as unchanged and unfamiliar forms as skipped with an explanation; never remove arbitrary `G4` instructions. Keep every `SAVE_VARIABLE`, other Box setup call, device placeholder and `SAVE_CONFIG` tail intact. A stock-template update should be a separate, reviewed decision so a later vendor config reset cannot silently undo the active-file change.

hlab already checks firmware/model and idle state, pauses the configuration agent, verifies a desktop recovery archive before writes, checks files again before applying, restarts Klipper, verifies controller startup and offers guarded rollback. Extend that mechanism rather than invoke Grease's installer. Tests should cover QIDI 1.8.2/2.1.1 stock and our modified Beacon macro, already-applied state, unknown macros, include-file ownership, line endings, preservation of unrelated text, rollback and effective loaded macro verification. Hardware acceptance remains one supervised Box start/print on each supported firmware configuration. [Existing hlab transaction](https://github.com/cl-tim/hlab/blob/e6f8b78d03f9193da8e48f0b928e23bda9089395/internal/printerlab/migration/tools/migration/apply-qidi-fixes.py), [CLI and existing scope](https://github.com/cl-tim/hlab/blob/e6f8b78d03f9193da8e48f0b928e23bda9089395/internal/printerlab/cli/firmware_fixes.go).

Persistent USB logging belongs in host tooling, not a Klipper config include. Reimplement a bounded, rotated, root-managed event sink with UTC time, boot identity, topology and vendor/product information, without serial numbers. Handle concurrent events and failed writes, and keep udev processing bounded. Preserve hlab's backup, check and rollback behavior. Validate recording across a reboot or controlled power cycle; do not deliberately disconnect a controller during a print. Installing the logger alone is insufficient: extend Klippee's bounded diagnostic collector and source parser to ingest the retained log and associate events with the correct boot/session.

Klippee already calculates pre-failure retransmit/sequence/CPU evidence, parses shutdown dumps, correlates nearby kernel USB events, and uses captured serial-to-topology mappings. Its collector reads the kernel journal with `journalctl --dmesg`. The new value is durable evidence across reboot, plus optional offline reporting if wanted; there is no need to port an entire second diagnosis engine. Missing USB events must remain inconclusive, and a USB disappearance does not by itself prove a mains-power fault. Local evidence: `klippee/public/install/klippee.py:3319`, `klippee/src/features/logDiagnostics/analyzer.ts:1129`, and `klippee/src/features/logDiagnostics/diagnosticUsbEvidence.ts:1`, reviewed at `ed24dc844e0964ab76cc175dfc766200a863653d`. hlab's existing [diagnostic upload bridge](https://github.com/cl-tim/hlab/blob/e6f8b78d03f9193da8e48f0b928e23bda9089395/internal/printerlab/migrate/klippee_diagnostics.go) provides the orchestration boundary.

If optional probing tuning is pursued, update both the configuration source and hlab's embedded `mainline-configs/mainline-klipper-beacon` copy with its provenance. A 600 mm/s motion ceiling is not validation of a 300 mm/s Beacon scan. Measure tilt repeatability, repeated mesh differences, scan coverage and actual elapsed time before changing the published validated profiles. No runtime config, hlab implementation or printer was changed by this review.

## Upstream feature detail

Grease is a Python 3.7 add-on for QIDI's existing Plus4 stack, rather than replacement firmware. Its installer recognizes the Plus4 model and accepts QIDI SOC V2.1.1, V1.8.2 and V1.8.1. There is also a hidden firmware override. Exact stock-text edits generally skip customized configurations; a separate switch allows replacement of user-defined probing speeds. [Identity/version checks](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/core.py#L77-L105), [CLI options](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/__main__.py#L15-L47).

| Change | Actual behavior | Adoption assessment |
|---|---|---|
| Box print-start waits | Removes sixteen `G4 P100` instructions while keeping each `SAVE_VARIABLE runout_N=0`. Nominal saving is 1.6 seconds when that branch executes. | A small candidate where our active macro still has this exact loop. Local vendor artifacts confirm synchronous write/reload; still verify the actual deployed patch and a Box print. |
| Stock G29 save wait | Changes both matched five-second delays before `SAVE_CONFIG_QD` to 0.5 seconds. | Only applies to the stock G29 flow. Do not transplant into Beacon workflows that already replaced it. |
| Z tilt speed | Changes XY travel speed from 150 to 300 mm/s. | Treat as tuning, with machine-specific movement validation. |
| Bed mesh speed | Changes travel/Beacon scan speed from 150 to 300 mm/s. | Treat as tuning; test the existing Beacon mesh behavior and results. |
| Persistent USB events | Installs a root-owned udev rule and helper, appending USB add/remove events to a log on eMMC. | A useful diagnostics candidate, preferably integrated with hlab collection rather than adding an unrelated installer. |
| Board fan, opt-in | Replaces the controller fan with a generic fan and a five-second control loop, using X/Y TMC2240 die temperatures and `U_1` MCU temperature. | Consider separately only if fan noise is an actual problem. |
| Chamber, opt-in | Replaces the physical chamber sensor with a 75% toolhead MCU / 25% chamber-thermistor mean, increases heater duty and temperature limit, removes QIDI chamber-target limits and bed assist. | Do not adopt as a general fix. This changes thermal policy and the meaning of the reported chamber temperature. |
| Box drying, opt-in | Adds macros for temperature, a minute-based duration and optional humidity hysteresis. | Do not copy unchanged; timer and changing-filament cases need correction. |

Sources: [default macro edits](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/edits.py#L76-L204), [fan and chamber edits](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/edits.py#L33-L73), [chamber policy](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/edits.py#L238-L301), [USB implementation](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/system.py#L1-L64), [dryer macros](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/plus4-grease-box-dry.cfg).

The fan uses driver ramps of 60–70 C and mainboard-MCU ramps of 45–65 C, with a 30% floor while X/Y are enabled or chamber heat is requested and full speed on shutdown. Those are chosen tuning values, not demonstrated defaults for every enclosure, fan or hardware revision. The chamber option raises `max_power` from 0.4 to 0.6 and `max_temp` from 70 to 80 C while retaining stock PID values. Its 70 C maximum sensor disagreement and separate heater protection are not evidence that the new control variable is accurate chamber air temperature. [Fan loop](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/edits.py#L51-L72), [complete chamber replacement](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/edits.py#L253-L298).

## Other features worth learning from

The optional Fluidd install serves patched upstream Fluidd v1.38.1 on port 81, with a separately namespaced settings database and a Plus4 Box card. It verifies a pinned bundle checksum, checks archive paths, tests nginx, reloads and probes the new site, and attempts rollback on installation failure. Precompressed assets, immutable caching for hashed assets and disabled access logging reduce page-serving work; there is a runtime-compression fallback when nginx lacks `gzip_static`. This is a separate UI product to maintain, not a prerequisite for the config fixes. [Fluidd version and bundle](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/fluidd.py#L33-L49), [nginx configuration](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/fluidd.py#L85-L143), [installation](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/fluidd.py#L358-L452), [Box UI patch](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/fluidd/plus4-grease.patch).

`klipper_report.py` summarizes MCU task load, host CPU use, serial retransmits, shutdown context and USB events from logs. `config_diff.py` compares section values and macro bodies with bundled stock files after reversing recognized Grease changes. These are useful diagnostic ideas to compare with existing tooling, rather than a reason to duplicate Klippee's analyzer. Their report is evidence to interpret, not authoritative root-cause detection: some branches turn correlation into categorical statements, such as treating lack of USB removal as proof of a firmware hang or treating certain scheduler messages as proof of excessive stepping. [Report logic](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/tools/klipper_report.py#L559-L630), [comparison logic](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/tools/config_diff.py#L104-L180).

Despite the README grouping it with read-only tools, `speed_test.py` is an active motion procedure. It homes, repeatedly drives an XY pattern, changes velocity limits and rehomes to compare step counts. It checks for an idle printer, prompts before motion, clips travel to no-print-zone boundaries and attempts to restore limits in `finally`. It also writes a report file. Any equivalent hlab feature needs explicit motion-test semantics and operator supervision. [Motion procedure](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/tools/speed_test.py#L114-L266).

## Correctness concerns before reusing code

1. **Drying does not re-evaluate filament limits during a session.** Startup calculates the minimum limit from occupied slots, but the periodic tick only checks heater-target ownership, duration and humidity. If a lower-temperature filament is inserted or a slot's filament identification changes while heating, this macro does not reduce or stop its existing target. Other QIDI components might act independently; the macro itself does not enforce its advertised filament limit continuously. [Startup checks](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/plus4-grease-box-dry.cfg#L87-L113), [tick](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/plus4-grease-box-dry.cfg#L156-L191).

2. **A small positive duration can run indefinitely.** `HOURS=0.001` passes validation and rounds to zero minutes. The tick only ends a timer at `minutes_left == 1`; zero keeps rescheduling with heat enabled. Reject durations below one supported tick or clamp a positive duration to at least one minute. [Conversion](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/plus4-grease-box-dry.cfg#L108-L125), [termination](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/plus4-grease-box-dry.cfg#L164-L190). This finding is static analysis, not a printer reproduction.

3. **Box timers share a reschedulable tick.** Starting any Box schedules the shared tick 60 seconds from that start. Starting another Box partway through a minute postpones the first Box's next decrement, so its duration extends. Absolute per-Box monotonic deadlines would avoid this drift. [Start scheduling](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/plus4-grease-box-dry.cfg#L119-L125), [all-Box loop](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/plus4-grease-box-dry.cfg#L156-L191).

4. **Installation rollback is narrower than an all-error transaction.** Config files are individually written with fsync and rename, backed up, and restored if the post-restart readiness check fails. Exceptions during multi-file writes or state persistence are not enclosed in that restoration branch. USB installation also writes two system files sequentially without cleanup when a later step fails. These are useful protections to emulate, but not a complete transaction implementation. [Atomic per-file write](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/core.py#L241-L258), [install sequence](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/core.py#L410-L454), [USB install sequence](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/system.py#L97-L114).

5. **Loaded-value verification only warns.** It detects a later include overriding an edited speed, but prints a note and returns installation success. Our tooling should verify the effective loaded setting and distinguish unapplied intent from a successful change. [Loaded-setting check](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/grease/core.py#L352-L373).

## Evidence and test limits

Upstream reports 117 passing tests, including exact stock edits and round trips against bundled V2.1.1 and V1.7.1 files. Its documented real-printer results come from one Beacon-converted V2.1.1 Plus4 with a Box. Firmware 1.8.1 and 1.8.2 are accepted on inference, not tested on those firmwares. The test log explicitly leaves stock-probe motion, stock G29 saving, Grease-installed fan/chamber changes, timed drying and several UI actions untested on hardware. These limits matter more than the number of unit tests. [Test log and explicit gaps](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/docs/testing.md#L5-L44).

The dryer tests model rendered Jinja and command state using a fake printer. They cover ordinary duration expiry, humidity hysteresis and four simultaneous Boxes, but do not exercise wall-clock postponement of the shared scheduler, a sub-minute duration rounding to zero or changed filament limits during a session. The fan/chamber tests check text installation and removal, not thermal performance. [Dryer tests](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/tests/test_box_dry.py#L172-L298), [fan/chamber install tests](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/tests/test_grease.py#L341-L393).

Local fixture verification used native Windows Python. The unmodified log-report suite encountered unsupported `os.nice`; with an in-process no-op shim, 26 of 29 cases passed, with two failures and one error involving motor/config extraction from CRLF fixtures. Three of five config-diff cases passed; two failed expected exact-edit/added-section comparisons in the Windows CRLF checkout. These runs do not establish a clean upstream test gate or a Linux-printer defect. Jinja2 was unavailable in the existing Python environments, so the dryer findings remain static analysis; no dependencies were installed. The synthetic report created by the test was removed.

For the runout wait specifically, local extracted QIDI vendor files for baseline 1.8.2 and the V2.1.1 update contain identical `cmd_SAVE_VARIABLE` implementations: write through `ConfigParser`, close the file, then call `loadVariables()` before returning. Both files have SHA-256 `0327ce54b1a7286d97b0b2fbe008ecc9a36057a5d12642fd6237552c5e77b682`. This supports removal of the inter-command delay for these builds; it does not establish fsync/power-loss durability. Evidence is local, untracked vendor material under `qidi-plus4-firmware/artifacts/vendor-firmware/2026-11-11/{baseline-1.8.2,aliyun/rootfs}/home/mks/klipper/klippy/extras/save_variables.py`, lines 90–112, not a public source link.

The upstream license is GPLv3, and its notice attributes Fluidd and Valve Oil code as well as QIDI stock text. Review provenance and license compatibility before copying implementation into a differently licensed project. [License](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/LICENSE), [source attributions](https://github.com/JarvisAKF/Plus4-Grease/blob/abc21a33b73758d34573d5f80de6b436d3241564/NOTICE.md).

Adoption order: exact Box wait removal where present, then persistent USB evidence integrated with the existing collection/analyzer, then measured probing speed tuning only if needed. Keep thermal-policy changes, a second Fluidd installation and a new dryer controller outside the default fixes. The local comparison above identifies the applicable files and implementation boundaries.
