# QIDI1: QIDI firmware 1.8.2, Beacon and QIDI Box

This is the current deployable configuration for the printer named `qidi1`.
It was refreshed from Klippee applied version 10 and verified against the
printer on 2026-08-06 at 14:31 AEST. The stable configuration matched; only Klipper's
per-printer `SAVE_CONFIG` calibration tail differed on the live machine.

QIDI1 runs QIDI's Klipper fork from firmware 1.8.2, a right-side Beacon Rev H,
one QIDI Box, a PB4-connected two-wire 5015 part-cooling blower, an 80 mm CPU
fan and a 120 mm chamber circulation fan. It is not interchangeable with the
mainline-Klipper QIDI2 profile.

## Managed configuration

`profile.json` is the authoritative file manifest. Its 16 managed `.cfg`
files are the exact stable set synced by Klippee. `printer.cfg` includes the
QIDI power-loss, Box, KAMP, timelapse, maintenance and Klippee integration
files; only `box1.cfg` is present because this printer has one physical Box.

`klippee-macros.cfg` is generated by `klippee install-moonraker`. It is kept
here because `printer.cfg` loads it, but it must not be edited by hand.

The current operational changes include:

- right-side Beacon offsets and a 180 C contact-probing safety limit;
- stable measured MZV input shapers at 55.8 Hz X and 41.4 Hz Y;
- guarded chute, cutter, pause and Box load/unload routes;
- a 20% chamber-circulation/carbon-filter floor while printing;
- QIDI Box startup purge compatibility plus validated cold-unload helpers;
- KAMP line purge, a 5 mm adaptive-mesh margin and brim-safe Voron purge; and
- manual-tramming preconditions, abort handling and current restoration.

The configured motion ceilings are 600 mm/s XY, 20,000 mm/s^2 XY,
20 mm/s Z and 500 mm/s^2 Z. These are firmware limits, not universal slicer
targets. Normal `PRINT_START` cleans through the factory chute with the
established 200 mm purge, cools and contact-homes the Beacon workflow, creates
an adaptive mesh, then lays down a separate 30 mm KAMP Voron prime.

## Private and volatile state

Before rendering, replace `CHANGE_ME_QIDI1_BEACON_SERIAL` and
`CHANGE_ME_QIDI1_BOX_SERIAL` with this printer's exact `/dev/serial/by-id`
paths. Klippee target rendering should perform that substitution.

The repository deliberately excludes `.klippee`, `saved_variables.cfg`,
actual USB identifiers, automatic backups, Beacon models, bed meshes and the
entire `#*# SAVE_CONFIG` tail. A pull/apply workflow must preserve the target
printer's existing calibration tail; never replace it with another printer's
state.

Run the repository guard before publishing a refresh:

```powershell
python scripts/verify_profiles.py
```
