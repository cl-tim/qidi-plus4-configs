# QIDI Plus4 mainline Klipper with Beacon

This is a complete upstream-Klipper profile for a QIDI Plus4 with the `X-7
1.0` mainboard, mainline Klipper on both UART MCUs, a right-side Beacon Rev H
mount, a PB4 white-port 5015 nozzle-cooling modification, and no QIDI Box. The
pin map and operating macros come from the commissioned profile in the
companion `qidi-plus4-firmware` repository.

This directory is a sanitized, deployable example validated on a commissioned
machine on 2026-08-03. It does not track that printer's identity or Klippee
history. `profile.json` records the exact ten-file runtime manifest.

It contains:

- `hardware.cfg`: MCU, pin, heater, fan, sensor, motion and bed geometry;
- `beacon.cfg`: Beacon, sensorless homing and resonance-test configuration;
- `production.cfg`: Purge Park, factory chute purge/eject, PEI and brush wipe,
  nozzle cooldown, Smart Park and adaptive Voron purge;
- `filament.cfg`: standalone cutter, load, unload and manual M600 handling;
- `utility.cfg`: drying, bed-level and input-shaper operator workflows;
- `operations.cfg`: mainline print, pause, resume, cancel, chamber and fan macros;
- `maintenance.cfg`: platform levelling, PID helpers and common G-code
  compatibility commands;
- `printer.cfg`: includes, host-facing objects and measured input-shaper values;
- `shaketune.cfg`: active Shake&Tune plugin configuration;
- `klippee-macros.cfg`: generated Moonraker sync controls;
- `ORCASLICER.md`: measured slicer speed and acceleration starting points.
- `QIDI-1.8.2-APPLICABILITY.md`: which factory 1.8.2 changes were carried to
  upstream Klipper, translated, or deliberately excluded.

## Before installation

This profile assumes that the host, mainboard and toolhead have already been
migrated to mainline Klipper. It is not compatible with the QIDI Klipper fork.
Do not use it on a different mainboard revision without reviewing every pin.

## Hardware deviations and measured values

Non-stock or machine-specific sections are marked directly in the configuration
with `[MOD]`, `[CALIBRATION]`, or `[TUNING]` comments:

| Marker | Section | Deviation |
| --- | --- | --- |
| `[MOD]` | `[beacon]` | Right-side Beacon Rev H with X=14, Y=-11 offsets. |
| `[MOD]` | `[fan]` | Two-wire 5015 nozzle-cooling fan moved from stock PA8/PA9 to the white PB4 port. |
| `[MOD]` | `[fan_generic chamber_circulation_fan]` | P3 controls a 120 mm chamber circulation fan. |
| `[MOD]` | `[temperature_fan adaptive_board_fan]` | Temperature control tuned for an 80 mm CPU fan. |
| `[CALIBRATION]` | `[input_shaper]` | Measured shaper frequencies and damping ratios; remeasure every printer. |
| `[CALIBRATION]` | `[hall_filament_width_sensor]` | Source-printer sensor values; the sensor ships disabled in this profile. |
| `[TUNING]` | `_QIDI_PRODUCTION_SETTINGS` | Stock-proven 80 mm chute clean plus a separate 30 mm Voron prime. |
| `[TUNING]` | Beacon and Z homing | Uses the proven QIDI 1.7.3/1.8.2 speeds: 300 mm/s XY transit, 150 mm/s pull-off, and 10/5 mm/s Z homing. |

The configured machine ceilings are 600 mm/s XY, 20,000 mm/s^2 XY,
20 mm/s Z and 500 mm/s^2 Z. The acceleration value is a firmware ceiling used
by the current Orca machine profile, not a claim that every feature or material
should print at 20,000 mm/s^2.

For a stock toolhead, restore the PA8 fan and PA9 tachometer mapping and add
PB4 back as QIDI's automatic `hotend_fan2`. Do not use the PB4 fan section as
written unless the white-port 5015 modification is installed.

Find the target printer's Beacon path:

```bash
ls -1 /dev/serial/by-id/usb-Beacon_*
```

Replace `CHANGE_ME_BEACON_SERIAL` in `beacon.cfg` with the exact result. Never
copy another printer's Beacon serial, saved model, mesh or PID values.

## Install

Back up `~/printer_data/config`, then copy the active files into that directory:

```text
printer.cfg
hardware.cfg
beacon.cfg
production.cfg
filament.cfg
utility.cfg
operations.cfg
maintenance.cfg
shaketune.cfg
klippee-macros.cfg
```

`shaketune.cfg` is included by the verified profile, so Klippain Shake&Tune
must be installed on the host. `klippee-macros.cfg` is generated by
`klippee install-moonraker`; keep it with the manifest but do not hand-edit it.

Restart Klipper and confirm every reported temperature is plausible before
moving an axis or enabling a heater.

On an already commissioned printer, render its unique Beacon serial and
preserve its per-printer `SAVE_CONFIG` calibration tail during apply. Generated
Beacon models and meshes are deliberately absent from this repository.

## Validate after installation

Run these as separate console commands before starting another sliced print:

```gcode
FIRMWARE_RESTART
G28
CLEAR_NOZZLE HOTEND=200 PURGE=0 PEI_WIPE=1
BED_MESH_CALIBRATE METHOD=beacon
```

The third command exercises the chute, ejector and both wiping surfaces without
purging filament. Keep a hand near emergency stop while
confirming those rear service-area moves for the first time. The final command
must move continuously across the bed; stop if it performs discrete point
probes. Once both pass, test the full purge with the intended filament loaded:

```gcode
CLEAR_NOZZLE HOTEND=220 PURGE=1 PEI_WIPE=1
```

## Platform calibration and maintenance helpers

`PLATFORM_CALIBRATE` mechanically synchronises the two Z drives by lowering
the bed slowly onto the printer's physical base stops at reduced motor current.
This is intentionally a hard-stop procedure. Remove tools and debris from the
printer base, make sure nothing obstructs the bed, stop all heater targets and
do not run it during a print. Then use:

```gcode
PLATFORM_CALIBRATE CONFIRM=YES
Z_TILT_ADJUST
```

`PLATFORM_CALIBRATION` is provided as an alias. A recovery timer restores the
normal Z-driver currents if the hard-stop sequence is interrupted. The profile
also holds both Z motors from startup onward to reduce bed drift. The sequence
is adapted from the pinned community
[`PLATFORM_CALIBRATION.cfg`](https://github.com/cgarwood82/plus4MainlineKlipperConfig/blob/e3551541f66860658de280b99f8c915a2bff5d34/config/macros/PLATFORM_CALIBRATION.cfg),
with additional heater, print-state and current-recovery safeguards.

Other imported or adapted helpers are:

- `FLUSH` parks at and empties the factory purge chute;
- `CUT_FILAMENT`, `LOAD_FILAMENT`, `UNLOAD_FILAMENT`, `M600`, `M603` and
  `M604` provide guarded standalone filament handling;
- `PREPARE_FILAMENT_DRYING`, `DRY_FILAMENT` and `STOP_DRY_FILAMENT` run the
  bounded chamber/bed drying workflow;
- `AUTO_BED_LEVEL`, `G29` and `AUTO_INPUT_SHAPER` provide familiar operator
  entry points without importing QIDI-only Python modules;
- `MUTE` retains and restores the operator's previous speed override;
- `PID_EXTRUDER`, `PID_BED`, and `PID_CHAMBER` run bounded PID tunes; add
  `SAVE=1` to save the result and restart Klipper automatically;
- `M303` maps conventional PID commands to those three heaters;
- `M290` supports bounded live Z adjustment;
- `M900` supports slicer pressure-advance commands; and
- `M0` maps a conventional program stop to the configured pause routine.

The community configuration's unhomed `SLOWnLOW`, obsolete
`ACCEL_TO_DECEL` override, automatic filament-width activation, duplicate
print lifecycle and older nozzle-cleaning macros are deliberately not carried
over. They are unsafe on unknown state, incompatible with current Klipper, or
superseded by this profile.

## Per-printer calibration

The Shake&Tune defaults were measured on the source printer after belt
tensioning, cleaning and lubricating the motion system. The measurement
recommends:

| Axis | Balanced shaper | Damping ratio | Approximate smoothing acceleration |
| --- | --- | ---: | ---: |
| X | `2hump_ei` at 76.4 Hz | 0.110 | 6180 mm/s^2 |
| Y | `ei` at 47.4 Hz | 0.060 | 4090 mm/s^2 |

The profile exposes the commissioned 20,000 mm/s^2 machine ceiling. The
measured shaper smoothing recommendations remain far lower and should guide
feature-specific Orca acceleration. Every other printer should rerun
`AXES_MAP_CALIBRATION`, `COMPARE_BELTS_RESPONSES`,
`AXES_SHAPER_CALIBRATION` and `CREATE_VIBRATIONS_PROFILE`.

Run fresh Beacon calibration, Z tilt, bed mesh and heater PID calibration on
the target machine. Klipper's `SAVE_CONFIG` output belongs only to that
printer and should not be committed to this template.

The supplied right-side Beacon offsets are `X=14`, `Y=-11`. Confirm the
physical mount before homing or scanning: an incorrect X offset can move the
sensor or toolhead outside the bed envelope.

## Production start sequence

The supplied `PRINT_START` is a complete single-material production sequence.
It uses the Plus4's factory chute and ejector, purges 80 mm in legal chunks,
wipes on the rear PEI area and silicone brush, cools the nozzle below 150 C,
contact-calibrates Z, runs proximity Z tilt and a continuous adaptive Beacon
scan with a 5 mm margin, contact-homes Z again, then applies 0.07 mm hot-nozzle
expansion compensation and uses Smart Park plus a 30 mm Voron prime. The
default soak is zero seconds and can be requested explicitly with `SOAK=`.

The physical cleaning coordinates are specific to the factory Plus4 hardware
and intentionally use the rear service area up to Y=324. Do not copy this file
to a different printer model. The standalone factory cutter is supported; the
QIDI Box and Happy Hare remain out of scope for this non-Box profile.

The scan method follows the current
[Beacon command reference](https://docs.beacon3d.com/commands/). The factory
cleaning geometry was cross-checked against the pinned
[Plus4 mainline configuration](https://github.com/cgarwood82/plus4MainlineKlipperConfig/tree/e3551541f66860658de280b99f8c915a2bff5d34)
and this repository's previously working 1.7.3 profile.
